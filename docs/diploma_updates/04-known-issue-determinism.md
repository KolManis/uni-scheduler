# НТ-6 «Воспроизводимость» больше не точна дословно

Касается `diploma_ch1.docx`, раздел 1.6.2, пункт НТ-6:

> **НТ-6. Воспроизводимость.** При одинаковых входных данных и параметрах система должна
> формировать одинаковое расписание (детерминированное поведение), что важно для отладки и
> сравнительного анализа.

(В `diploma_full.docx` такого явного пункта нет — там нефункциональные требования НТ-1–НТ-5
без отдельного пункта про воспроизводимость, так что это касается только ch1-версии, если
она в работе.)

## Почему это больше не совсем так

Конструктивная фаза (`SolveTeacher`) по-прежнему полностью детерминирована — никакой
случайности, тот же вход всегда даёт тот же начальный результат. А вот `iteratedLocalSearch`
(см. `02-algorithm-improvements.md`) использует `math/rand` для случайных возмущений —
значит, при повторном запуске на тех же данных финальный результат (после оптимизационной
фазы) может немного отличаться от запуска к запуску: разные случайные возмущения могут
найти разные улучшения за отведённое время.

## Варианты, как поступить (нужно ваше решение)

**Вариант А — переформулировать требование, не убирать.** Честно отразить, что
детерминизм гарантирован только для конструктивной фазы, а оптимизационная — управляемо
стохастична:

> **НТ-6. Воспроизводимость.** Конструктивная фаза алгоритма (`teacher-driven`)
> детерминирована: при одинаковых входных данных строит одинаковое начальное расписание.
> Оптимизационная фаза (итеративный локальный поиск) использует управляемую стохастику для
> преодоления локальных оптимумов, поэтому итоговый результат может незначительно
> отличаться между запусками на одинаковых данных, но гарантированно не хуже результата
> одного детерминированного прохода 2-opt/or-opt (см. доказательство монотонности в
> разделе о локальном поиске).

**Вариант Б — убрать требование как таковое.** Раз оптимизационная фаза всё равно не
обязана быть воспроизводимой (это не то, для чего систему делали), можно просто убрать
пункт НТ-6 из списка и не создавать формального противоречия.

**Вариант В — сделать по-настоящему воспроизводимым.** Технически возможно: принимать
seed для генератора случайных чисел как параметр (по умолчанию — время, но можно
зафиксировать явно). Это отдельная небольшая доработка кода (сейчас `rand.New(rand.NewSource(time.Now().UnixNano()))`
жёстко зашит внутри `iteratedLocalSearch`), не только правка текста — если выбираете этот
вариант, скажите, сделаю.

Я рекомендую **вариант А** — он самый честный и не требует правок кода, а нюанс
«детерминированная гарантия только для конструктивной фазы плюс монотонное улучшение»
неплохо смотрится с академической точки зрения (показывает понимание границ метода).
