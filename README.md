# uni-scheduler

Автоматическое составление недельного расписания занятий кафедры.
На вход — справочники (корпуса, аудитории, группы, преподаватели) и учебные планы,
на выходе — расписание с разбивкой по чётной и нечётной неделе, выгрузка в Excel.

Go 1.25, PostgreSQL 16. Веб-интерфейс `/ui/*` и REST API `/api/v1/*` работают поверх
одной бизнес-логики. Подробное описание для пользователя — раздел «Справка» в интерфейсе.

## Запуск

Нужен Docker с `docker compose`.

```bash
make up      # собрать образ и запустить postgres + приложение
make seed    # залить справочники из data/snapshots (очищает справочники!)
make demo    # запуск из уже собранного образа, без интернета
make test    # go build + go vet + go test
make help    # все команды
```

Интерфейс: http://localhost:8080/ui/schedules


## Структура

Гексагональная архитектура: ядро не зависит от адаптеров.

```
cmd/                         точка входа
cmd/bench/                   бенчмарк солвера на данных из БД
internal/core/domain/        доменные типы
internal/core/app/           сценарии: генерация, перенос пары, импорт
internal/core/ports/         интерфейсы хранилищ
internal/core/solver/        алгоритм составления расписания
internal/adapters/in/http/   REST API и веб-интерфейс
internal/adapters/in/excel/  разбор Excel при импорте
internal/adapters/out/postgres/  хранилище
migrations/                  схема БД (0002 не подключается — конфликтует с 0001)
deploy/                      конфигурация для сервера
```

## Алгоритм

1. **Построение.** Преподаватели обрабатываются от самых ограниченных по времени к самым
   свободным; каждая пара ставится в слот с наименьшим штрафом. Одно занятие плана ставится
   всем его группам одновременно, без деления на подгруппы.
2. **Улучшение.** Локальный поиск (перестановки пар) и один из методов на выбор: iterated
   local search, имитация отжига, табу-поиск, генетический алгоритм, LNS.
3. **Оценка.** Штрафы за окна, дни с одной парой, субботу, перегрузку дня, переходы между
   корпусами — отдельно для чётной и нечётной недели, итог — среднее.

Жёсткие ограничения не нарушаются никогда: преподаватель, группа и аудитория не заняты
дважды одновременно, недоступные слоты преподавателя, тип и вместимость аудитории, корпуса.

Результат не зависит от порядка входных данных: солвер сортирует их перед построением.

## REST API

База: `/api/v1`

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/schedules/generate` | Сгенерировать расписание |
| GET | `/schedules` | Список расписаний |
| GET | `/schedules/{id}` | Расписание целиком |
| DELETE | `/schedules/{id}` | Удалить расписание |
| PATCH | `/schedules/{id}/assignments/{idx}` | Перенести одну пару |
| GET | `/schedules/{id}/excel?type=all_teachers\|all_groups` | Выгрузка в Excel |
| POST | `/import/excel` | Импорт справочников из xlsx |
| GET, POST, PUT, DELETE | `/buildings`, `/departments`, `/rooms`, `/groups`, `/teachers`, `/subject-plans` | Справочники |

Пример генерации:

```json
POST /api/v1/schedules/generate
{
  "name": "Осень 2026",
  "timeout_sec": 120,
  "improve_algo": "hillclimb",
  "lecture_practice_same_day": false,
  "lecture_before_practice": false,
  "same_subject_same_day": false
}
```

`improve_algo`: `hillclimb` | `sa` | `tabu` | `ga` | `lns`.
Три последних поля — необязательные мягкие правила, по умолчанию выключены.

## Бенчмарк

```bash
go run ./cmd/bench -runs 5 -budget 60s -methods hillclimb,sa,lns > bench.csv
```

Несколько прогонов каждого метода на данных из БД; в CSV — score, окна и дни с одной парой
по чётной и нечётной неделе.
