# ADR-0014: Инкрементальная оценка хода и новые окрестности

Принято · 2026-09-24

## Контекст
Каждый пробный ход копировал весь массив пар, заново строил карту занятости и пересчитывал
штраф всего расписания — O(n) на ход при O(n²) ходов за проход 2-opt. На 362 парах один проход
сходимости занимал ~35 с, и при бюджете 45 с метаэвристикам почти не оставалось времени.
Отсюда вывод ADR-0012 «методы дают близкие результаты»: они просто не успевали работать.

## Решение
- **Инкрементальная оценка** (`evaluator.go`). Штрафы разложены по владельцам: всё, что считает
  оценка для группы (окна, форточки, перегрузки, переходы, одиночная суббота, мало дней,
  необязательные правила), зависит только от пар этой группы; для преподавателя — только от
  его пар. Ход пересчитывает только затронутых; жёсткие ограничения проверяются по индексу
  занятости (сущность × слот × неделя). Значение совпадает с `calculateFitness` бит в бит —
  проверяется тестом на реальных справочниках после тысяч случайных ходов с откатами.
- **Новые окрестности**: перенос пары с подбором другой допустимой аудитории, смена аудитории
  на месте, обмен днями группы (все пары группы из дня A в день B и обратно), or-opt внутри
  того же дня.
- **LNS — настоящее разрушение-восстановление**: пары снимаются до восстановления, набор
  выбирается в том числе «связанно» (группы одного потока, преподаватель целиком), трудные
  ставятся первыми.
- **Отжиг**: T₀ подбирается по среднему ухудшающему ходу, охлаждение по времени.
- **Табу**: запрет по атрибуту «пара возвращается в покинутый слот» вместо запрета хода.
- **ILS**: принимается равный score, толчок растёт с застоем.
- **Генетический**: каждый потомок дошлифовывается or-opt (меметический алгоритм).

## Подтверждение
`go run ./cmd/bench -snapshots data/snapshots -runs 2 -budget 45s`, 362 пары, все поставлены.
Окон у групп нет в обеих версиях.

| Метод | Было, score | Стало, score | Дней с одной парой (чёт/нечёт): было → стало |
|---|---|---|---|
| Iterated local search | 44 230–44 600 | 4630–5060 | 11–12 / 7 → 1 / 0 |
| Отжиг | 44 600–45 000 | 5430–5530 | 12 / 7 → 1 / 0 |
| Табу | 44 230 | 6130–8230 | 11 / 7 → 1–2 / 0 |
| Генетический | 38 300–39 190 | 4830–5090 | 9 / 6 → 1 / 0 |
| LNS | 38 300 | 5190–5470 | 9 / 6 → 1 / 0 |

## Последствия
- Метод по умолчанию (ILS) теперь не хуже остальных и обычно заканчивает раньше бюджета.
- Табу-поиск отстаёт: выборка из 100 случайных соседей для него слабая окрестность.
- Отжиг использует весь бюджет; табу, отжиг и генетический после бюджета делают финальную
  сходимость (до 5 с) — таймаут генерации оставляет на это 15 с.
- `checkHardConstraints` и `calculateFitness` остаются эталоном: ими проверяются результат
  и тесты.
