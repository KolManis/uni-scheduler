# ADR-0009: Качество оценивается по чётной и нечётной неделе отдельно

Принято · 2026-09-23 · `7ed2811`

## Контекст
У 215 из 320 учебных планов задана чётность. Оценка сливала обе недели в одну: пара «только
по чётным» считалась занимающей слот и в нечётную неделю, где он на самом деле пуст. Реальные
окна и форточки были не видны. Расписание #48 по оценке и по реальным неделям:

| | Окна | Дни с одной парой |
|---|---|---|
| Как считала оценка | 2 | 0 |
| Реальная чётная неделя | 13 | 40 |
| Реальная нечётная неделя | 3 | 20 |

Все прежние отчёты «0 окон, 3 форточки» были верны только для этой условной объединённой недели.

## Решение
- Штрафы (окна, форточки, перегрузки, переходы, суббота) считаются для каждой недели — пары
  «всегда» плюс пары своей чётности — и усредняются. Окно в одной неделе весит половину
  еженедельного. Без пар с чётностью результат прежний.
- Построение смотрит на реальную неделю каждой пары и тоже усредняет.
- Счётчики качества — отдельно для чётной и нечётной недели.

## Последствия
- «Мигалка» получается сама: пара по чётным охотнее встаёт туда, где у группы пара по нечётным,
  закрывая окно (на эталонном примере сходимость собрала такую без специального кода).
- Оценка по двум неделям примерно вдвое дороже; за 60 с методы GA и LNS не выходят за пределы
  начальной сходимости. Нужна инкрементальная оценка.

## Подтверждение
Бенчмарк 5 × 3 по 60 с, реальные недели:

| | Прежний алгоритм | Новый |
|---|---|---|
| Окна, чёт/нечёт | 2–13 / 3–6 | 0–1 / 0 |
| Дни с одной парой, чёт/нечёт | 36–40 / 15–20 | от 7/8 до 27/18 |

`TestCalculateQuality` (пара только по чётным) и `TestSlotPenalty_BlinkingPairFillsOtherWeekGap`
падают без учёта недель.
