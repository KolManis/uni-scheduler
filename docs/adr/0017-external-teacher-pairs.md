# ADR-0017: Пары преподавателей на других факультетах — жёсткое ограничение

Принято · 2026-09-24

## Контекст
Цель — одна общая генерация на весь вуз, но данных других факультетов пока нет. Сейчас
кафедре сообщают, когда у её преподавателей пары на других факультетах; двигать их нельзя,
расписание кафедры строится вокруг них.

«Недоступные пары» (HC7) для этого не подходят: они без чётности (пара «по нечётным» на другом
факультете закрывала бы слот и в чётную неделю) и не отличают «не могу» от «занят там-то».

## Решение
- У преподавателя поле `external_pairs`: слот, чётность, пометка (факультет, предмет, аудитория).
  Хранится JSONB-колонкой в `teachers` (миграция 0006), отдельная таблица пока не нужна.
- Для алгоритма это занятость преподавателя в свою чётность — расширение HC7:
  - построение считает эти слоты уже занятыми (`occupiedTeachers`), гибкость преподавателя
    уменьшается (пара «всегда» — на слот, по чётности — на половину);
  - `teacherUnavailable` хранит для слота чётность занятости; оценщик и `checkHardConstraints`
    проверяют пересечение недель;
  - ручной перенос отклоняется с `teacher_unavailable`, если недели пересекаются.
- В score внешние пары не входят: окна и нагрузка преподавателя считаются только по парам
  кафедры. Иначе оценка зависела бы от данных, которые кафедра не контролирует.
- Ввод — таблица в форме преподавателя и поле в REST `/teachers`.
- Миграции 0003–0006 идемпотентны; `make db-migrate` накатывает их на рабочую базу без потери
  данных (раньше новая миграция требовала пересоздания тома).

## Подтверждение
- Тесты: чётность внешней пары учитывается в `checkHardConstraints` и оценщике; оба построения
  не ставят пары на время внешних и ставят все пары.
- Проверено на PostgreSQL 16: миграции 0003–0006 дважды накатываются на базу со старой схемой;
  форма сохраняет и показывает пары; генерация через API не ставит пары преподавателя на время
  внешней; ручной перенос на это время — 409 `teacher_unavailable`, по другой неделе — разрешён.

- Показ: на странице расписания «по дням» — серыми строками «Другой факультет: <пометка>» у
  преподавателей этого расписания, без кнопки «Изменить»; в Excel «Все преподаватели» и по
  одному преподавателю — серой ячейкой. В расписании групп их нет: это чужие группы.
- Ручной перенос на время внешней пары отклоняется отдельным конфликтом
  `teacher_external_pair` с пометкой и неделей пары — чтобы было видно, почему нельзя.

## Последствия
- Импорт из Excel внешние пары не читает.
- Когда появится общая генерация, внешние пары станут обычными парами других кафедр, а поле
  останется для факультетов, которые в систему не войдут.
