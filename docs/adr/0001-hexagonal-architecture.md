# ADR-0001: Гексагональная архитектура

Принято · 2026-09-22 · `cd744bd`

## Контекст
Прежняя структура (`domain/`, `usecase/`, `repository/`, `transport/`) нарушала правило
зависимостей: сценарии импортировали пакет Postgres ради типа `ScheduleSummary`, веб-интерфейс
вызывал солвер напрямую в обход сценариев. REST API и веб-интерфейс могли разойтись в поведении.

## Решение
- `internal/core/` — ядро: `domain` (типы), `app` (сценарии), `ports` (интерфейсы хранилищ),
  `solver` (алгоритм). Ядро не импортирует ни один адаптер.
- `internal/adapters/in/` — входящие адаптеры: `http/rest`, `http/web`, `excel`.
- `internal/adapters/out/postgres` — хранилище.
- REST API и веб-интерфейс вызывают одни и те же сценарии.
- `TimeSlot` — объект-значение: приватные поля, конструктор с проверкой; некорректный слот
  («воскресенье, 9-я пара») создать нельзя.

## Альтернативы
Оставить слоистую структуру и исправить два нарушения точечно. Отклонено: без явного деления
на ядро и адаптеры нарушения появляются снова.

## Последствия
- Солвер и сценарии тестируются без БД и HTTP (заглушки через порты).
- Хранилище или транспорт заменяются без правки ядра.
- Веб-форма больше не может создать некорректный слот: раньше он собирался из ввода без проверки.

## Подтверждение
Проверка графа зависимостей: ядро импортирует только ядро и стандартную библиотеку.
49 эталонных ответов REST и веб-интерфейса совпали побайтно до и после переноса.
