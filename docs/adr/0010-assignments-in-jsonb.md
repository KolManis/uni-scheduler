# ADR-0010: Пары расписания хранятся одним JSONB-полем

Принято · до 2026-09 (исходное решение проекта)

## Контекст
Расписание — несколько сотен пар (362 на текущих данных). Оно всегда читается и сохраняется
целиком: генерация, просмотр, выгрузка, ручной перенос одной пары с пересчётом score.

## Решение
Таблица `schedules`: `assignments JSONB`, `unplaced JSONB`, `options JSONB`, `score`, `created_at`.
Чтение JSONB — через `decodeJSON`: `NULL` оставляет поле пустым (старые расписания до миграций
0004 и 0005), повреждённый JSON — ошибка с указанием записи и поля.

## Альтернативы
Отдельная таблица пар (одна строка на пару). Отклонено для текущего масштаба: запросы вида «все
пары преподавателя во всех расписаниях» не нужны, а атомарное сохранение целого расписания проще.

## Последствия
- Сохранение и чтение — одна строка.
- Аналитика по парам в SQL — через `jsonb_array_elements`.
- При переходе на весь университет и совместное редактирование решение стоит пересмотреть.
