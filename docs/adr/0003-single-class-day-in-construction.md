# ADR-0003: Дни с одной парой устраняются при построении

Принято · 2026-09-23 · `9878fbe` (неудачная попытка — `17c661d`) · соотношение штрафов заменено ADR-0016

## Контекст
В расписаниях было около 26 дней, когда у группы одна пара: студент едет ради одной пары.
Штраф за это в оценке был 25 — на два порядка меньше штрафа за окно (10 000).

## Неудачная попытка
Поднять штраф в оценке до 8000 (`17c661d`). Замер, 5 методов × 3 прогона по 60 с:

| | До | Штраф 8000 |
|---|---|---|
| Дни с одной парой | ~26 | 23–28 |
| Окна у групп | 1 | 9–11 |

Локальный поиск склеивал два одиночных дня в один день с окном: −2 × 8000 + 10 000 выгодно
для оценки, но не для студентов.

## Причина
Построение само создавало одиночные дни: поставить пару в пустой день стоило 0, в день, где у
группы уже одна пара, — 800. Первые пары групп разбрасывались по неделе, и локальный поиск
не мог собрать их обратно без окон.

## Решение
- При построении: пустой день +1500, день с одной парой 0, с двумя +1000.
- В оценке штраф за одиночный день 4000 — меньше половины штрафа за окно.

## Подтверждение
5 методов × 3 прогона: 0 окон и 3 дня с одной парой в 14 прогонах из 15; выброс — один
прогон SA (19 дней). `TestSlotPenalty_PrefersDayWithSinglePair` падает на старых весах.

## Последствия
Вывод для работы: штраф в оценке не исправит того, что построение делает систематически.
Сначала искать, откуда дефект берётся.
