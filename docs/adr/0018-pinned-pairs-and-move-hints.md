# ADR-0018: Закрепление пар, подсказка переноса и вид по преподавателям

Принято · 2026-09-24

## Контекст
Расписание на кафедре сейчас составляют вручную, и составитель будет править результат
системы руками. Три проблемы:
- при ручном переносе время и аудиторию выбирали наугад, о конфликте узнавали после сохранения;
- любая повторная генерация начиналась с нуля и теряла все ручные правки;
- сетки по преподавателю на сайте не было, только выгрузка в Excel.

## Решение
- **Подсказка переноса** (`app.MoveOptions`, `GET …/options`): для каждого из 36 слотов —
  можно ли туда перенести пару с её чётностью, в какую аудиторию (своя, иначе первая свободная
  из подходящих по HC4–HC6, `solver.SuitableRooms`) и как изменятся score, окна, окна в 2+ пары,
  дни с одной парой и суббота. В форме переноса — сетка «пара × день»: зелёные клетки
  переносят пару одним нажатием, жёлтые — перенос возможен, но откроет окно в 2+ пары, серые —
  нельзя, с причиной. Проверка конфликтов общая с ручным переносом (`moveConflict`): сначала
  преподаватель и группы, аудитория последней — её конфликт устраним.
- **Закрепление** (`Assignment.Pinned`, хранится в JSONB пар — миграция не нужна): кнопка
  «Закрепить» у пары, `PUT …/pinned`. **Перегенерация** (`base_schedule_id`,
  `solver.SolveWithFixed`) строит новое расписание вокруг закреплённых пар исходного:
  построение ставит их первыми и засчитывает их часы, `evaluator.apply` отвергает любой ход,
  меняющий их слот или аудиторию, LNS их не снимает, вставка не вытесняет. Построение и правила
  берутся из исходного расписания; исходное остаётся в списке.
- **Вид по преподавателям** (`/ui/schedules/{id}/teachers`): сетка «пара × день» для каждого
  преподавателя этого расписания, окна подсвечены, пары на других факультетах — серым.
- Исправлено попутно: ручной перенос в аудиторию другого корпуса оставлял у пары прежний
  `building_id`, и переходы между корпусами считались неверно.

## Подтверждение
- Тест: на реальных справочниках каждый из пяти методов оставляет закреплённые пары (каждую
  седьмую) на месте и в той же аудитории, ставит все остальные, жёстких нарушений нет.
- Проверено на PostgreSQL 16: сетка переноса (36 клеток), перенос по зелёной клетке — 200,
  по серой — 409; закрепление через форму и REST; перегенерация сохранила обе закреплённые пары
  и все 44 пары; вид по преподавателям показывает пары на других факультетах.

## Последствия
- Ручной перенос на жёлтую клетку разрешён: решение за человеком, окно видно в блоке качества.
- Подсказка считает оценку заново для каждого слота (36 × полный пересчёт); на 362 парах это
  доли секунды, инкрементальная оценка здесь не нужна.
