# Развёртывание

## Разработка
`make up` — сборка образа и запуск PostgreSQL + приложения (порт 8080).
`make demo` — запуск из готового образа без интернета. `make seed` — справочники из
`data/snapshots` (очищает справочники). `make test` — build + vet + test.
Схему базы создаёт и обновляет приложение при старте (goose, ADR-0024): отдельного шага
«накатить миграции» нет, новые миграции приходят с новым образом.

## Сервер кафедры
`make package` собирает `dist/uni-scheduler.tar.gz`:

| В архиве | Зачем |
|---|---|
| `images.tar` | образы приложения и PostgreSQL — сервер без интернета |
| `docker-compose.yml` | запуск из образов, без сборки |
| `.env.example` | порт (по умолчанию 18080), пароль БД |
| `initdb/seed.sql` | дамп рабочей базы без строк расписаний: схема, справочники, `goose_db_version` — база на сервере сразу в текущей версии |
| бинарники Linux и Windows | запуск без Docker |

PostgreSQL наружу не публикуется: нет конфликта с занятым 5432, база не видна из сети.
Образы собраны под x86-64.

## Сервер с интернетом
Образ собирается на сервере из репозитория (`docker build`), запуск — тот же
`deploy/docker-compose.yml`, папка `initdb/` пустая. Приложение создаёт схему с демо-справочниками
(0001), `scheduler seed` заменяет их данными кафедры, встроенными в бинарник (`data/snapshots`,
ADR-0025). При сохранённых расписаниях `seed` отказывается без `-force`. Обновление — `git pull`,
`docker build`, `docker compose up -d`.

Проверка пакета: распаковка и запуск «как на сервере» на отдельном порту, сверка справочников
с рабочей базой, генерация, просмотр, Excel.
