# ADR-0012: Пять методов улучшения на выбор, сравнение в одном запуске

Принято · 2026-09-22 · `262b4e0`, `9d09991`, `acf3812`

## Контекст
После построения расписание улучшается локальным поиском (перестановки пар, 2-opt и or-opt).
Он застревает в локальном оптимуме. Внешние библиотеки оптимизации (CP-SAT и подобные) требуют
C++-зависимостей или отдельного сервиса; решено остаться на чистом Go.

## Решение
Пять методов поверх общей сходимости, один интерфейс, выбор параметром `improve_algo`:

| Метод | Идея |
|---|---|
| Iterated local search | сходимость; застряв — случайный толчок и снова сходимость |
| Имитация отжига (SA) | принимает ухудшения с вероятностью exp(−Δ/T), T падает |
| Табу-поиск | лучший из ~100 соседей, недавние ходы запрещены |
| Генетический алгоритм | популяция 16 расписаний, турнирный отбор, кроссовер, мутации |
| LNS | снять 20% пар и расставить их лучшим образом заново |

Режим «Все методы» запускает пять параллельно и сохраняет пять расписаний.

## Найденные по ходу проблемы
- Параллелизм умножался: 5 методов × 8 стартов = 40 горутин на 4–8 ядер, score деградировал
  в 5–7 раз (170–213 тыс. против ~30 тыс.). Исправлено: при «Все методы» старты игнорируются.
- Бюджет солвера был захардкожен 60 с независимо от таймаута пользователя; при параллельном
  запуске все методы возвращали одинаковый score сырого построения (148 270). Бюджет теперь
  берётся из таймаута.

## Последствия
На текущих данных методы дают близкие результаты: качество в основном определяет построение
(ADR-0003, ADR-0009). Разброс между прогонами одного метода часто больше разницы между
методами — сравнивать только сериями прогонов.
