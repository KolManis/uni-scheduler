# ADR-0013: Чётность и частоту пар выбирает алгоритм

Предложено · 2026-09-23

## Контекст
Сейчас в учебном плане задаются часы в неделю и чётность (всегда / чётная / нечётная). В данных
чётность задана у 215 из 320 планов — она перенесена из старого расписания, а не требуется
нагрузкой. Реальная нагрузка кафедры задаёт часы **за семестр** по видам занятий: например,
«Базы данных», РИС-25-1б — 116 ч лабораторных; «Проектирование программных интерфейсов»,
РИС2-23-3б — 20 ч практик и 40 ч лабораторных.

В данных встречаются схемы «каждую неделю + ещё через неделю» (6 случаев, все — лабораторные)
и пары «по чётным» + «по нечётным» одного предмета у одной группы (9 случаев).

## Предлагаемое решение
1. Шаг 1 — без новой модели данных: чётность пар «через неделю» выбирает алгоритм (при
   построении пробовать обе недели для каждого слота; в локальном поиске — ход «сменить неделю»).
   Перенесённые чётности перевести в «выбирает алгоритм», прежние значения сохранить.
2. Шаг 2 — вход в виде часов за семестр: алгоритм подбирает схему (каждую неделю, через неделю,
   каждую неделю + через неделю) под число недель семестра.

## Открытые вопросы (к руководителю)
Число недель в семестре; чётность первой недели; подгруппы на лабораторных (116 ч у одной
группы ≈ 3,6 пары в неделю); правило округления часов; какие виды нагрузки ставятся в сетку;
формат, в котором нагрузка придёт в систему. Полный список — отдельный документ вопросов.

## Ожидаемые последствия
Больше свободы для «мигалок» (ADR-0009) и меньше окон в каждой неделе. Шаг 2 меняет модель
учебного плана, импорт и форму — нужны миграция и пересчёт существующих данных.
