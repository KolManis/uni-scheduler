# ADR-0019: Сценарии — команды и запросы; проверка данных, причины неразмещения, DSatur по умолчанию

Принято · 2026-09-24

## Контекст
Слой сценариев (`internal/core/app`) был одним файлом `service.go` на 500 строк: генерация одним
методом и всеми методами повторяли друг друга почти целиком (загрузка, фильтр по половине
семестра, бюджет, сохранение), перенос пары и подсказка переноса жили в разных местах, а имена
(`PatchAssignment`, `GenerateInput`, `GetByID`) не говорили, что сценарий делает.

## Решение
- **Команды и запросы.** Один сценарий — один файл: `command_*.go` меняют данные
  (`GenerateSchedule`, `GenerateAllMethods`, `MoveAssignment`, `PinAssignment`, `DeleteSchedule`,
  `ImportExcel`), `query_*.go` только читают (`GetSchedule`, `ListSchedules`, `MoveOptions`,
  `CheckInput`). Вход команды — структура с говорящим именем (`GenerateCommand`,
  `MoveAssignmentCommand`, `PinAssignmentCommand`), в ней всё, что нужно сценарию, включая id.
  Оглавление — в комментарии пакета (`service.go`). Проверки жёстких ограничений — в
  `conflict.go`, одни для ручного переноса, подсказки и причин неразмещения.
- **Генерация** — одна подготовка (`prepareGeneration`) и одно «составить и сохранить»
  (`solveAndSave`) для обоих режимов; значения по умолчанию — именованные константы.
- **Проверка данных до генерации** (`CheckInput`, `GET /input/check`, блок на странице списка
  расписаний): план без преподавателя или групп, без подходящей аудитории, нечётные часы;
  преподаватель, которому не хватает свободных пар; группа, у которой пар больше, чем слотов;
  нагрузка больше указанного максимума (пары «через неделю» считаются за половину).
- **Причины неразмещения** (`UnplacedItem.Reason`) считаются после генерации и показываются в
  отчёте «Не удалось разместить» вместо общего списка «возможных причин».
- **DSatur — построение по умолчанию** (`solver_type` пустой): по замерам ADR-0016 он с
  локальным поиском даёт лучший и самый стабильный результат.
- **CI** (`.github/workflows/ci.yml`): сборка, `go vet`, `gofmt`, тесты на каждый push.

## Подтверждение
- Все тесты прошли без изменения ожидаемых результатов после переноса сценариев (кроме
  переименований вызовов). Новые тесты — на проверку данных и на причину неразмещения.
- На реальных справочниках (`data/snapshots`) проверка не нашла ошибок и дала 3 предупреждения:
  нагрузка трёх преподавателей больше их максимума часов.

## Последствия
- Адаптеры вызывают сценарии по новым именам; поведение REST API не изменилось, кроме пустого
  `solver_type` (теперь DSatur) и нового поля `reason`.
