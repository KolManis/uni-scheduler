# ADR-0025: Установка на сервер с интернетом — сборка на сервере и `scheduler seed`

Принято · 2026-09-25

## Контекст
Установка была одна — из пакета `make package` (образы и дамп базы), рассчитанная на сервер
без интернета. Если интернет на сервере есть, пакет лишний: образ можно собрать из репозитория,
а обновление свести к `git pull` и пересборке. Мешали две вещи:

- `deploy/docker-compose.yml` требовал файл `seed.sql`, который появляется только в пакете;
- без него новая база получала демо-справочники из миграции 0001, а реальные заливал только
  `scripts/migrate.*` — ему нужны Go на машине (очистка через `go run`) и база, открытая наружу с
  паролем разработки. На сервер это не переносится.

## Решение
- **Справочники кафедры встроены в бинарник** (`data/snapshots`, пакет `snapshots`, загрузчик
  `Load`; им же пользуется `cmd/bench`).
- **Команда `scheduler seed [-force]`** заменяет справочники в базе встроенными
  (`RefWriteRepository.ReplaceReferences`) с их ID. Если в базе есть расписания, без `-force`
  отказывается: пары расписаний ссылаются на ID справочников и перестали бы открываться (DB-005).
- **`seed.sql` необязателен**: compose подключает папку `initdb/` целиком. В пакете там
  `seed.sql`, при установке из git — только README, который Postgres пропускает.
- Установка с интернетом: `git clone`, `docker build`, `docker compose up -d`,
  `docker compose exec app /scheduler seed`. Обновление: `git pull`, `docker build`, `up -d`.

## Альтернативы
- **Готовый образ из GitHub Container Registry** — обновление без сборки на сервере, но образ
  публичный и нужен шаг публикации в CI. Оставлено на потом.
- **Загружать справочники автоматически при старте, если в базе демо-данные** — меньше шагов,
  но неявно: приложение само меняло бы данные. Команда явная и повторяемая.

## Подтверждение
- `TestLoad_Embedded`: встроено 2 корпуса, 8 кафедр, 31 аудитория, 39 групп, 51 преподаватель,
  320 планов.
- `TestReplaceReferences` (тег `integration`): новая база — демо-справочники заменены; есть
  расписание — отказ, справочники не тронуты; с `force` — заменены. Без проверки расписаний
  кейс с отказом падает.
- Установка «как с сервера» в отдельной папке и отдельном проекте compose: схема 0→8, после
  `seed` — справочники кафедры, генерация, повторный `seed` отказывает (код 1), после
  перезапуска расписание на месте, после пересборки образа миграции 8→8.
- Пакет с `initdb/seed.sql`: база из дампа, приложение 8→8, справочники на месте.
