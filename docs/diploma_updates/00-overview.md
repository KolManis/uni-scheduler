## Коротко: что реально изменилось в коде с момента написания текста

1. **Появился веб-интерфейс** (`internal/transport/http/web/*`) — раньше была только
   декларация «REST API». Теперь есть полноценные HTML-страницы: CRUD для всех
   справочников, генерация и просмотр расписания (по дням и **по группам** с подсветкой
   окон), ручное редактирование занятия прямо в браузере, разбивка score по категориям.
   Диплом сейчас нигде это не описывает и не упоминает в заключении как «сделано».
2. **Локальный поиск переписан.** Было: один проход 2-opt, потом один проход or-opt.
   Стало: `converge` (2-opt+or-opt по очереди до совместной сходимости) +
   `iteratedLocalSearch` (классический iterated local search — возмущение и повторная
   сходимость, чтобы выбираться из локальных оптимумов, которые чистый 2-opt/or-opt не
   видит). Текст диплома описывает старую, более простую версию.
3. **Добавлено разбиение потоков** (`placeGroupsSplit`) — если у многогруппового
   факультативного занятия (например, физкультуры на 7 групп) нет общего слота на всех
   сразу, алгоритм рекурсивно делит состав пополам и ищет слот для каждой половины
   отдельно. Заодно исправлен реальный дефект: раньше такие занятия вообще не пытались
   размещаться (тихо пропускались), а не «не находили слот» — в тексте диплома это нигде
   не упомянуто, потому что на момент написания текста таких предметов в данных не было.
4. **Появился отчёт о неразмещённых занятиях** (`ComputeUnplaced`) — раньше система молча
   теряла то, что не поместилось. Теперь по каждому расписанию фиксируется, какая
   дисциплина/тип/группа не влезла и почему (сколько часов не хватает).
5. **Появилась разбивка штрафной функции по категориям** (`CalculateFitnessBreakdown`) —
   раньше score был просто числом, теперь пользователь видит вклад каждой из 10 категорий.
6. **Вторая верификация на реальных данных** — датасет расширен общеобразовательными
   предметами других кафедр (математика, философия, история, психология, физкультура в
   зале/на улице, БЖД, начертательная геометрия) — 320 планов вместо 286, 362 занятия.
   Это хороший материал для диплома: показывает систему не только на «удобных» данных
   одной кафедры, а на межкафедральном сценарии с реальными конфликтами.
7. **`solver_type` в API поддерживает не только `teacher`.** Текст говорит «единственное
   поддерживаемое значение — teacher», но в коде есть ещё `subject` (запасной
   backtracking-алгоритм), доступный пользователю как явный выбор — это была неточность
   ещё до моих правок, не только следствие новых изменений.
